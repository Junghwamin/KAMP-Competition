# 피처 제거 확인 실험 — 계획서

작성 2026-09-25 · 대상: 최종모델 **2단계 레짐(3분류)** · 원본 저장소는 건드리지 않는다.

## 1. 왜 하는가

6.3절 Ablation(`outputs/tables/ch2_ablation.csv`)에서 피처군을 빼자 오히려 좋아진 행이 있었다.

| 제거 피처군 | OOF MAE | 변화 | Recall | 변화 |
|---|---|---|---|---|
| (기준: 전체 44개) | 11.007 | — | 0.846 | — |
| 과거 전력 지연변수 6개 | **7.876** | **−3.131 (−28%)** | 0.859 | +0.013 |
| 기상정보 6개 | 10.985 | −0.021 | 0.853 | +0.006 |

과거 전력 지연변수를 빼면 MAE와 Recall이 함께 좋아지는데, 이 모델은 최종모델 선정 후보에 없었다.
**최종모델을 바꿔야 하는지** 판단하려면 아래 질문 네 가지에 답해야 한다. 현재 표는 4개 fold를 합산한 값 하나뿐이라 이 질문에 답할 수 없다.

1. 개선이 **하계휴가(07-31~08-08) 전후에만** 생기는가, **정상 가동일**에도 생기는가?
2. 6개 중 **어떤 지연변수**가 문제인가(24·48·168시간)? 통째로 빼야 하는가?
3. 지연변수를 빼는 대신 **휴무 인지형 지연변수**(휴무일을 건너뛴 과거값)로 바꾸면 어떤가?
4. 44개 피처를 **하나씩** 빼 보면 빼서 좋아지는 피처가 잡음 이상으로 있는가?

## 2. 원칙 (미리 고정)

- **테스트(9/1~9/14)를 보지 않는다.** 판단은 fold 2~5 검증(OOF)으로만 한다. 스크립트는 테스트 데이터를 읽지 않는다.
  최종모델을 바꾸기로 결정되면 원본 저장소에서 후보 목록에 추가하고, 스코어카드로 선정한 뒤 FULL로 다시 실행한다. 테스트 결과는 그때 나오는 대로 보고한다.
- **FULL 설정 그대로**(`KAMP_FAST=0`) 실행한다. 레짐 모델은 Optuna를 쓰지 않으므로(`LGB_BASE`, 트리 800·게이트 400) 레짐 모델만 따로 돌려도 본실행과 같은 모델이 나온다.
- **코드는 원본 그대로 쓴다.** 원본 복사본 `KAMP-Competition/src`의 s00~s03을 import해 실행한다. s05의 `LGB_BASE`·`run_cv`·`make_regime_model`은 AST로 원문을 추출해 실행한다(s05를 import하면 5장 전체가 돈다).
- **짝지은 비교**: 모든 변형이 같은 행(D1 사용가능 행)과 같은 fold를 쓴다. 차이는 일 단위 블록 부트스트랩(`paired_bootstrap_mae`, 2,000회)으로 검정한다.
- 복사본에서만 실행한다. s00~s03 import가 복사본의 `outputs/`에 표·그림을 쓰지만, 원본은 바뀌지 않는다.

## 4. 실험 변형

| ID | 내용 | 확인하려는 것 |
|---|---|---|
| A | 기준(44개) | — |
| G-* | 피처군 6개를 하나씩 제거(과거전력·이동통계·시간정보·공정상태·생산정보·기상정보). 생산정보는 원본과 같이 게이트도 생산량 비의존으로 교체 | 기존 Ablation 재현 + 빠졌던 두 군(이동통계·시간정보) |
| L24 / L48 / L168 | 해당 지연 2개(평균·peak)만 제거 | 문제가 되는 지연이 무엇인가 (질문 2) |
| B+W | 지연 6개 + 기상 6개 동시 제거 | 두 개선이 더해지는가 |
| SA-all | 지연 6개를 **휴무 인지형**으로 교체 | 질문 3 |
| SA-168 | lag168 2개만 휴무 인지형으로 교체(24·48은 그대로) | 원인이 lag168인가 |
| LOFO-* | 44개 피처를 하나씩 제거 (44회) | 질문 4 |
| NULL-0~4 | 순수 잡음 피처 1개 추가(시드 5개) | **잡음 기준선**: 의미 없는 변화가 MAE를 얼마나 흔드는가 |

**휴무 인지형 지연변수 정의**
- 대상일 D의 휴무 여부(`is_shutdown`, 일생산량 = 0, 계획값이므로 원점에서 알 수 있음)를 기준으로 삼는다.
- 원래 참조일(D−1, D−2, D−7)의 휴무 여부가 D와 다르면 더 과거로 한 칸씩 물러난다.
  - 24·48시간은 1일 단위로, 최대 14일까지 물러난다.
  - 168시간은 7일 단위(같은 요일)로, 최대 5주까지 물러난다.
- 끝까지 없으면 NaN으로 둔다(LightGBM이 결측을 처리).
- 참조일은 항상 D−1 이전이므로 원점 D−1 24:00 기준으로 인과적이다.

## 5. 측정 지표

- OOF 전체: MAE, Peak-MAE(θ=187), Recall·F1·FP(τ = fold τ 중앙값, 기존 Ablation과 같은 방식), fold MAE 표준편차
- **fold별 MAE**: fold 2(07-07~07-20)와 fold 5(08-18~08-31)는 휴가가 없는 **정상 fold**이고, fold 3·4는 휴가와 재가동을 포함한다.
- **구간별 MAE**
  - **lag168 불일치일**: 대상일과 7일 전의 휴무 여부가 다른 날(휴가 시작·재가동 주간 등)
  - **일치일**: 그 밖의 날
  - 휴무일과 가동일을 따로 보는 분해도 함께 본다.
- 기준 A 대비 차이의 부트스트랩 95% CI와 p값

## 6. 판단 기준 (결과를 보기 전에 고정)

**잡음 폭** = NULL 5회의 |ΔMAE| 최댓값. 이 폭 안의 변화는 "차이 없음"으로 본다.

변형 V는 다음을 **모두** 만족할 때만 **최종모델 교체 후보**로 판정한다.
1. OOF MAE 개선의 부트스트랩 95% CI가 0을 포함하지 않는다.
2. **정상 fold 2·5 각각**에서 A보다 나빠진 폭이 잡음 폭 이하이다.
3. **lag168 일치일**(정상일)에서 A보다 나빠진 폭이 잡음 폭 이하이다.
4. Recall이 A보다 0.01 넘게 낮지 않고, Peak-MAE가 A보다 **Peak-MAE 잡음 폭**(NULL 5회의 |ΔPeak-MAE| 최댓값) 넘게 나빠지지 않는다.
5. D2 조건(복제일 제거)에서도 개선 방향이 같다. 후보에 대해서만 추가로 확인한다.

**해석 규칙**

| 결과 | 결론 |
|---|---|
| 지연 제거(G-과거전력)가 1~5를 통과 | 지연 제거가 정당한 후보다 → 원본에 후보로 추가할지 사용자가 결정 |
| 개선이 불일치일·휴가 fold에만 있고 SA가 1~5를 통과 | **휴무 인지형 지연변수**가 올바른 수정이다(정상일 정보를 보존함) |
| 모두 불통과 | 최종모델을 유지하고, 보고서 문구를 실측 기반으로 바꾼다("정상 구간에서 유용"은 현재 측정 근거가 없는 문구) |
| LOFO에서 잡음 폭을 넘어 **4개 fold 중 3개 이상**에서 좋아지는 피처 | 개별 제거 후보로 따로 보고한다. 44개를 동시에 비교하므로 우연히 걸리는 것이 있을 수 있다는 점을 명시한다 |
