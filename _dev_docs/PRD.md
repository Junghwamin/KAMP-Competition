## 2. 확정 기술 계약 (Contract) — 3장 이후 모든 코드가 이 정의를 공유한다

> **이 절이 PRD의 핵심이다.** 여기서 정의한 이름·정의는 어떤 단계에서도 재정의·재계산하지 않는다.

### 2.1 타깃 정의

```
y_avg   = 평균                                   (kW, 시간별 평균전력)
y_peak  = peak15 = max(15분, 30분, 45분, 60분)    (kW, 시간 내 15분 최대수요)
y_cls   = 1[y_peak >= THETA]
```

⚠️ `15분` 단일 컬럼을 쓰면 q95/q99/max가 173.6/188/207로 **보고서 수치(187/201/222)와 불일치**한다. 가이드북 베이스라인은 `15분`만 쓰므로 **따라가면 안 된다.**

### 2.2 임계값 — 기호 2종을 엄격히 분리

| 기호 | 의미 | 산출 범위 | 값 |
|---|---|---|---|
| **THETA (θ)** | 피크 **정의** 임계값 | 학습 전체구간 q95에서 **1회**, 7/13·7/15 **포함** | **187 고정** |
| **TAU (τ)** | **판정/경보** 임계값 | **각 fold 검증구간에서만** 산출 | 모델·fold별 가변, 테스트용은 fold τ 중앙값 |

- θ는 **단일 상수 셀**에 존재하고 `assert THETA == 187`로 고정을 증명한다. 어떤 fold도 재계산하지 않는다.
- 근거: fold별 학습구간 q95는 **182/182/184/186/186** — 어느 fold에서도 187이 안 나온다. fold마다 재산출하면 `y_cls` 정의 자체가 달라져 fold 간 Recall 평균이 무의미해진다.
- τ는 회귀→판정 경로에 **필수**다. 동일 LightGBM 예측값에 θ=187 고정 시 Recall 0.143 / F1 0.235, 검증셋 τ=182 적용 시 Recall 0.500 / F1 0.538 (3.5배). 2.7절 표에 **각 행이 쓴 τ를 컬럼으로 노출**한다.

### 2.3 Day-ahead 원점 (누수 차단의 기준선)

```
origin(D+1) = D일 24:00  (= D+1일 00:00, D일 24개 시간값의 관측이 완료된 시점)
```

- **`D일 23:00`은 결함이다** — `h=23`에서 `lag24`의 참조 시각이 `D일 23:00`인데 이 값은 23:00~24:00 구간 집계이므로 origin 시점에 아직 미완성이다.
- 안전 lag: `shift(24)`, `shift(48)`, `shift(168)`만 사용.
- **이동통계는 origin 기준 1회 계산 후 24시간 브로드캐스트.** `rolling(24).mean().shift(1)`은 `h>0`에서 누수 → **금지**.
- `min_periods`: 168창=168, 24창=24. 워밍업 탈락 행 수를 출력.
- 누수 assert 기준은 "참조 시각 ≤ origin"이 아니라 **"값의 관측완료 시각(= 참조 시각 + 1시간) ≤ origin"**.
- **기상변수는 실측을 D+1 예보의 대리(proxy)로 사용**한다는 가정을 명시.

### 2.4 마스크 3종

| 마스크 | 대상 | 행 수 | 처리 |
|---|---|---|---|
| `is_outage` | 센서측 계측정지 08-28 18시~08-29 10시 | 17 | 시간보간 + **지표 계산에서만 제외** |
| `is_erp_missing` | ERP측 결측 7/13·7/15 | 48 | **θ 산출엔 포함**, 평가·**학습 모두에서 제외** |
| `is_warmup` | lag/rolling 워밍업 탈락 | 계산값 | 학습·평가 제외 |

- `is_erp_missing` 48행은 `생산량=0`인데 평균전력 135.9(정상 비가동 44.8) → 2단계 레짐의 비가동 회귀를 오염시키므로 **학습에서도 제외**.
- 계측정지는 **보간으로 확정**(NaN 아님). NaN이면 `rolling(168, min_periods=168)`이 테스트 09-01~09-05의 120/336시간(35.7%)을 소실시켜 "336행·결측 0" 검증과 정면 충돌한다.

### 2.5 데이터 조건 2축

| 조건 | 정의 | 일수 |
|---|---|---|
| **D1** | 복제 유지 (원형) | 257일 |
| **D2** | 복제 제거 (각 중복그룹에서 1일만 잔류) | 142일 |

- **구현 결정(고정)**: 노트북 본문 서사는 **D1로 일관 진행**한다. `for` 루프는 마크다운으로 분리된 셀을 가로지를 수 없으므로, **3~7장의 모든 함수는 `data_cond` 인자를 받고**, 전용 절 `### 6.5 데이터조건 D2 재실행`에서 D2로 재호출하여 대비표 + 순위보존 검증을 산출한다. → **3단계 이후 모든 함수 시그니처가 여기에 걸린다.**
- 최종모델은 **D1 기준 선정**, D2 순위 보존을 강건성 근거로 2.9절 3)항에 추가.
- D2는 fold 경계 실제 일수가 줄어들므로 **fold별 표본수 n을 표에 병기**.

### 2.6 분할

- 테스트: **2021-09-01 00:00 ~ 09-14 23:00, 336시간 고정**
- Rolling-origin, 검증 각 14일, expanding 학습, **학습종료–검증시작 24시간 갭**
- **fold1 폐기 → 4-fold** (복제 오염 50%, D1·D2 공통 폐기)

| fold | 학습 종료 | 검증 | 휴무일 비중 |
|---|---|---|---|
| ~~1~~ | ~~06-21~~ | ~~06-23~07-06~~ | **폐기(오염 50%)** |

- 스케일러·결측 대치 기준 = **각 fold 학습구간에서만**, τ = **각 fold 검증구간에서만**, θ = **고정**.

### 2.7 평가지표

- **Task A 주지표 MAE**, 보조 RMSE · sMAPE(분모 `(|y|+|ŷ|)/2`, 0 제외) · **Peak-MAE**(`y_peak ≥ θ`인 시각만)
- **Task B 주지표 = F1 / PR-AUC** (Recall 아님 — 재정의 필수)
  - 이유: 달력규칙 한 줄(`평일 ∧ 08≤h≤18`)이 테스트에서 **Recall 1.000**(TP 28, FN 0, FP 82, TN 226). **어떤 ML 모델도 Recall로는 못 이긴다.**
  - 주지표를 **"Recall 유지하면서 오경보(FP) 최소화"**로 재정의. 2.7절 표에 **달력규칙 행을 기준으로 추가**하고, 기여를 **"동일 Recall에서 FP 82건 → N건"**으로 정량화.
- **모델 비교의 주 근거 = Rolling-origin fold 분포**(양성 합계 185건). 테스트 336시간은 최종 확인용 단일 수치.
  - 테스트 피크 28건은 8개 날짜·16개 연속 블록 → 유효 표본 8~16. Recall 0.357 기준 Clopper-Pearson 95% CI 폭 **0.37** → 두 모델 구분 불가.
- Recall CI = **Clopper-Pearson 정확 이항**, 부트스트랩 쓰면 **일(day) 단위 블록 부트스트랩**.
- **PR-AUC 정규화**: fold별 양성률이 5.95~17.26%(2.9배) → **lift(PR-AUC/양성률)** 병기 + fold별 양성수·양성률 표기.
- **MAE 개선 유의성**: 시간별 절대오차 벡터에 **paired bootstrap** → 95% CI·p-value. 검증기준은 "MAE가 낮을 것"이 아니라 **"차이의 95% CI가 0을 포함하지 않을 것"**.
- **1h-ahead**는 가이드북 직접비교용 → **Seasonal Naive·RNN·RF·최종모델 4개로 한정**.

### 2.9 사양 정정 3건 (데이터 실측으로 확인)

1. **`인건비`는 금액이 아니라 교대 배수**. `==1.0`은 **9~17시만**, `h==8`은 **항상 1.5**. 요일 분포 균등 → **주말 할증 없음**. 예외 18행은 7/13·7/15뿐.
2. **`공장인원`은 인원수가 아님**. 0~48.39 연속 실수(고유 3,432개), 생산량과 corr 0.785 → **정규화 투입 공수**. 가이드북 셀 83의 `NumVar(1,75,'공장인원 수')`는 단위 오해.
3. **공휴일 리스트가 틀림**. 2/11(127.3)·3/1(129.0)은 **정상 가동일**. 하계휴가 **07-31~08-08 9일**이 통째로 누락. → 하드코딩 금지, **데이터 기반 가동 캘린더**(`일생산량 합 == 0` → 휴무)로 판정.

## 5. 개발 아키텍처 — "코드 1벌, 노트북은 빌드 산출물"

### 5.1 원칙

**구현은 한 벌만 존재한다.** `build/stages/*.py`가 단일 진실원이고, `.ipynb`는 거기서 조립된 빌드 산출물이다. 노트북에 붙여넣은 사본을 따로 유지하지 않는다(반드시 드리프트한다).

- 포맷: **jupytext percent** (`# %%` 코드셀 / `# %% [markdown]` 마크다운셀) — jupytext 1.19.1 설치 확인
- 테스트는 `build/stages/*.py`를 **import** 한다. import 시 해당 장이 실제 데이터로 실행되므로, 테스트가 "함수가 돈다"가 아니라 **"이 장이 실제로 돈다"**를 증명한다.
- 장 간 변수 전달: `# %% tags=["nb-strip"]` 셀에 `from s01_diagnose import df_clean` — 빌더가 이 태그 셀을 **삭제**한다(노트북은 동일 커널에서 변수가 이미 존재). 이 변환은 `tests/test_build.py`가 검증한다.
- 함수 정의는 **노트북 셀 안에 그대로 보인다**(plan §12.4 셀 구성 규칙: 마크다운 → 코드 → 출력, 함수마다 docstring + 인라인 주석).

### 5.2 FAST 모드

`KAMP_FAST=1` → `n_trials` 100→6, RNN epochs 500→5, MLP 300→5, `n_estimators` 축소.
**테스트는 FAST, 노트북 본실행은 FULL.** 없으면 매 pytest가 15분+이고 D1/D2로 2배가 된다.

## 8. 저감 레버 4종 (4장 10점)

**공통 원칙: 일일 총생산량을 보존한 채 시간 배치만 바꾼다** — 생산을 줄이는 게 아니라 옮기므로 매출 손실이 없다. 이것이 4장의 설득력이다.

| 레버 | 조정 | 근거 | 비용·부작용 |
|---|---|---|---|
| **L1** 설비 기동시점 분산 | 08시 일제기동 → 08:00/08:20/08:40 계단식. 13시 동일 | 08시 피크율 **24.7%**(1위), 13시 17.3%. 7→8시 87.6→121.3 = 동시기동 돌입전류. 222 중 3건이 08시 | 생산량·인건비 불변 → **최우선 권고**. 08시는 인건비 1.5 구간 |
| **L2** 고생산 시간대 이동 | 피크시간 생산량 일부를 같은 날 저부하(10~11,15~16시)로 | 생산량–전력 corr 0.518. 10시 114.8·15시 110.9·16시 112.5 여유 | 공정순서 제약 시 제한. 일 총생산량 보존 |
| **L3** 시간당 생산량 상한 | 피크위험 시간 상한 + 초과분 다음시간 이월 | L2의 자동화 버전, 예측 `peak15` > 임계 시 발동 | **이월 잔량 0 검증 필수** |
| **L4** 야간·주말 이전 | 주간 고부하 일부를 야간·주말로 | 토 51.1 / 일 41.3 여유. 정상일 야간피크 0건 | **야간=인건비 1.5배**. **주말 할증은 이 데이터상 0**(§2.9) → 실제 특근수당 파라미터 노출. **반드시 순절감액으로 판정** |

**요금 구조**: 한전은 **3개월 최대피크로 12개월 청구** → 목적함수는 평균이 아니라 **최대값(max) 저감**.
`절감액 = Δ최대수요(kW) × 기본요금단가(원/kW·월) × 12 + 시간대이동 전력량요금 차액 − 인건비 증가분`
기본요금 단가는 검증 불가 → **파라미터 + ±30% 민감도 표**. 전력 단위(kW)는 명시적 가정.

⚠️ **9월 테스트 구간만으로는 절감액이 0원**이다(7~9월 창 최대 = 222(7월), 9월 204를 0으로 낮춰도 청구 피크 불변).
➡️ 8장 시뮬레이션 대상을 **전체기간(01-01~09-14) 실측 `peak15` 시계열**로 확대. 9월 결과는 "운영 시나리오 검증"으로만 제시하되 **"이 구간 단독으로는 연간 기본요금에 영향 없음"을 명시**(정직성 가점).
⚠️ 설비 ID 부재 → L1 효과는 **데이터로 산출 불가**. `α`(08시 피크 중 동시기동 기여분) 가정 파라미터 + α=10/20/30% 민감도. 시나리오 표에 **'모델기반 / 가정기반' 열**로 근거 강도 구분.
