## 시청 순서

1편(용어 지도)을 먼저 보세요. 2~7편은 코드가 실제로 흘러가는 순서 — **학습 → 번들 저장 → 같은 모델 증명 → 검증하며 읽기 → 하루치 예측 → CLI·API** — 를 따라갑니다. 편마다 앞부분에 과제 맥락과 '지금 전체 흐름의 어디쯤인가' 지도를 넣어 한 편만 봐도 이해되게 했습니다.

## 화면의 숫자는 어디서 왔나

- 모든 수치는 저장소(`KAMP-Competition`)의 **FULL 실행 번들을 이 PC 에서 직접 돌려 잰 값**입니다. 번들 매니페스트와 같은 라이브러리 버전(lightgbm 4.7.0 · numpy 2.3.5 · pandas 3.0.5)으로 실행했고, 저장소 파일은 읽기만 했습니다(변조 실험은 번들 **복사본**으로 했습니다).
- 씬 코드는 그 결과 파일에서만 값을 읽습니다. 손으로 옮겨 적은 숫자는 없고, 대본의 모든 숫자는 결과 파일과 자릿수까지 대조했습니다.
- 대본의 주장은 검사식(불변량)으로 걸었습니다 — 예: 리플레이 336행이 제출 파일과 전부 일치(MAE 5.2199), bundle_id 끝 12자리 = 매니페스트 지문, 배포 번들의 τ 출처 = 평가 번들, 게이트 트리 1200그루 = 3 × 400.
- 지연시간·로드 시간은 **이 PC 에서 잰 값**이라 다른 컴퓨터에서는 달라집니다.

## 화면 속 코드 읽는 법

화면의 코드는 저장소 원문을 그대로 잘라 온 것입니다. 다만 영상 글꼴(고정폭)에 한글이 없어 두 곳을 바꿔 적었습니다.

- `"..."` — 한글 오류 메시지 문자열을 줄인 것
- `"<rain>"` 같은 꺾쇠 — 한글 컬럼명(강수량)을 저장소 API 가 쓰는 영어 별칭으로 바꿔 쓴 것
  (`<date>` 날짜 · `<hour>` 시간 · `<avg>` 평균 · `<p15>` 15분 · `<prod>` 생산량 · `<headcount>` 공장인원 · `<temp>` 기온 · `<wind>` 풍속 · `<humid>` 습도 · `<rain>` 강수량 · `<labor>` 인건비)

코드 옆에는 원본 위치(예: `serving/bundle.py:168-227`)를 적었습니다.
